## 0. 原則

**P0 は単一の数値目標ではない。族ごとの証明書のベクトル値判定である。**

`rank > 6` / `χ > 36` / hyperedge order `> 4` の三択にしてはならない。
同じ数値「6」でも族ごとに意味する資源が異なるため、**その族固有の単位**で立てる必要がある。

| 競合族 | 凍結資源 | 排除に必要な証明書 |
|---|---|---|
| D-classical | 古典状態数 `D_cl ≤ 6` | classical Hankel rank `> 6` |
| A-hidden GKSL | hidden Hilbert次元 `D_hidden ≤ 6` | `dim K > (d·D_hidden)²`（qubitなら **> 144**） |
| E-process tensor | memory bond dimension `χ ≤ 36` | temporal-cut operator Schmidt rank `> 36` |
| DQ-QHMM | quantum memory次元 `D_q ≤ 6` | QHMM固有の次元下界（定義依存） |
| C-synchronization | hyperedge order `≤ 4` | irreducible order `> 4`（**独立gate。他族を排除しない**） |

系が qubit なら族Aの上限は `(2·6)² = 144`。**スカラー Hankel rank を族Aへ流用してはならない** —
より自然には reachable-observable space そのものについて `dim K > 144` を認証する。
族Eの operator Schmidt rank も別の flattening・別の minor・別の摂動評価を要する。

## 1. 各証明書は「入れ子」でなければならない

**平坦な容量超過だけでは、「低容量モデルには最初から表現不能な過程を選んだ」という自明な勝利になる。**
matched-pair の物語が成立しない。

さらに重要な点として、**容量の上界は競合の存在を保証しない。**
有限 Hankel rank `≤ 6` が直接保証するのは6次元以下の**線形／quasi-HMM**実現であり、
確率非負性を持つ古典 HMM の存在には追加の実現可能性条件が要る。
**この非対称性は全族に共通する** — CP/TP・comb条件・positivity はいずれも次元の線形勘定では出ない。

| 証明書 | calibration側（**存在**を示す） | full側（容量超過を示す） |
|---|---|---|
| **P0-D** | `∃` 6状態以下の古典HMM。明示構成 or 非負性feasibility（LP） | `rank H_{C∪T} ≥ 7` |
| **P0-A** | `∃` `D_hidden≤6` の**GKSL-admissible** dilation（CP/TP・積初期状態・ancilla readout禁止込み） | `dim K_full > (d·D_hidden)²` |
| **P0-E** | `∃` `χ≤36` の**妥当な** process tensor（comb条件・positivity込み） | `OSR_c(Υ_full) ≥ 37` |
| **P0-DQ** | `∃` `D_q≤6` の QHMM（**定義を先に固定**） | 定義固有の spectral／factorization invariant |
| **P0-C** | order `≤ 4` で calibration が合う | irreducible order `> 4` |

**P0-D の厳密形:**

```
∃ M_D,  D_cl ≤ 6 :  P_{M_D}(w) = P_*(w)  ∀w ∈ C
                     rank H_{C∪T} ≥ 7
```

第一行が「calibration に本当に適合する競合が存在する」、第二行が「full data には適合不可能」を保証する。

> ⚠️ **Hankel 部分行列の prefix–suffix 閉包に注意。**
> calibration と held-out から作る行・列集合は、正しい prefix–suffix 構造を持つよう設計すること。
> 単にデータ点を表形式で切り分けるだけでは Hankel 部分行列にならない。

### QHMM の閾値を安易に書かないこと

Hilbert次元 `D_q` の量子モデルは演算子空間に `D_q²` 程度の線形自由度を持つため、
粗い排除条件は `rank H > D_q²`（`D_q≤6` なら `> 36`）が候補になる。
**しかしこれは QHMM の instrument構造・stationarity・pure/mixed memory・出力規約に依存する。**

classical Hankel rank ／ PSD-rank・quantum factorization dimension ／ spectral invariant ／
quantum memory cost を**分離**し、D05（Riechers–Elliott, arXiv:2509.03004）と
D06（Zonnios, arXiv:2412.12812）が実際にどの QHMM 定義へ下界を与えるかを固定してから閾値を書く。
単純に `> 6` や `> 36` と書くのは危険。

## 2. ノイズ頑健版

族Dについて、観測誤差による行列摂動を `‖ΔH‖₂ ≤ τ_H` と抑えれば、Weyl の不等式から

```
σ_7(H_full + ΔH) ≥ σ_7(H_full) − τ_H > 0
```

となり、`rank ≥ 7` がノイズ下でも維持される。**判定条件は `σ_7(H_full) > τ_H(α)`。**

> ⚠️ **【2026-07-26 §4quater で差し替え】判定対象は `H_full`（43×43）ではなく
> 行・列語がすべて長さ2の 8×8 部分行列 `H_wit` とし、条件は `σ_7(H_wit) > τ_H(8; α)` とする。**
> 43×43 版は凍結 shot 予算では測定できない（深さ4語 1296 個が必要、予算は 64 protocol）。

族Eには `σ_37` を operator-Schmidt flattening に対して、
族Aには reachable-observable map に対して、**それぞれ別に**定義する必要がある。

**τ_H の目安（要確認）:** 2000 shots/protocol、成分あたり統計誤差 `≈ 1/√2000 ≈ 0.022`。
`30×30` 程度の Hankel 行列なら、ランダム行列の評価で `‖ΔH‖₂ ≈ (√m+√n)·σ_entry ≈ 0.24`。
（Frobenius 評価 `√(mn)·σ_entry ≈ 0.67` は緩すぎる）
**σ₇ がこの水準を超えられるかは、構成前にスモークで確認する。**

### 4.2 ⚠️ held-out 側の shot 予算が存在しない【本体】

| m | depth2未使用 | depth3未使用 | depth4固定 | 全held-out shots |
|---:|---:|---:|---:|---:|
| 6 | 14 | 96 | 64 | 348,000 |
| 8 | 34 | 312 | 64 | 820,000 |

**depth-4 の64 protocol だけで 128,000 shots となり、calibration 総上限 `1.2×10⁵` を単独で超える。**
m=8 の全held-out は calibration 予算の約7倍。

`1.2×10⁵` が calibration 専用なのか総予算なのかが未定義であり、
held-out 検証のコストがどこにも計上されていない。

### 4.3 「両順序測定」の解釈が未確定

上表は「1 edge あたり2 protocol（両順序）」で計算している。
しかし出典 `.tex` の `SU(d)` gauge fitting では **1 edge あたり7 measurements**（`7(m−1)` calibration）だった。
この規約なら m=8 で depth2 だけで `11×7 = 77` protocol、合計109 protocol = **218,000 shots** となり
calibration 単独で上限を82%超過する。

### 4.4 ⚠️「7 measurements」は setting 数であることが確定【出典から逆算】

`docs/source-material/..._2026-07-23.tex` の tree-scaling 表から、1 edge あたりの測定数を逆算した。

| model | m | gauge次元 q | calibration | spanning tree | 測定/edge |
|---|---:|---:|---:|---:|---:|
| SU(2) | 4, 8, 16, 32 | 3 | 21, 49, 105, 217 | 3, 7, 15, 31 | **7.0**（全て） |
| SU(3) | 4, 16 | 8 | 54, 270 | 3, 15 | **18.0**（両方） |
| permutation | 6 | — | 20 | 5 | **4.0** |

**測定/edge が gauge 次元 `q` に比例している。** protocol 数なら `q` に依存しないため、
これは **gauge元を同定するのに必要な測定設定数**である。よって：

- **「両順序測定」= 1 edge あたり 2 protocol**（介入の順序2通り）
- **設定数はそれとは独立の因子**であり、同定対象の自由度で決まる
- 予算の原子単位は **protocol-setting pair**：`N_shots = Σ_p Σ_{s∈S(p)} n_{p,s}`

### 4.5 【凍結】ステップ1の決定事項

> **`1.2×10⁵` shots は calibration 専用上限とする。**
> **held-out 認証は独立予算とし、depth-4 全64 protocol を実施する場合の最低予算を `1.28×10⁵` shots とする。**
> **protocol と measurement setting を分離して計上し、`2000` shots は一律値ではなく一設定あたりの上限とする。**
> **標準探索は `m=6`、`m=8` は予算拡張を要する stress test とする。**

**shots/setting の二段階配分**（すべて上限 `2000` 以下、追加shotの判定規則は事前登録すること）

|---|---|

| rank-revealing な depth-4 | 2000 |
| 補助 held-out（depth-2/3 未使用） | 500–1000 |
| 境界的な測定のみ | 追加shot（規則を事前登録） |

**実行可能な標準設計は「calibration + depth-4」。全held-out は追加検証。**

## 4ter. ステップ2の結果【2026-07-25 実施 — 判定: **GO**】

`scripts/sigma7_smoke.py`。理想データ（ノイズなし）で到達可能な `σ₇` を測定した。

### 構造の確定

- 応答模型 `R(w) = p† M_{w_k}···M_{w_1} c`（SMRT/RISEI と同形）
- Hankel `H[u,v] = R(u·v)`、prefix/suffix は長さ ≤2 → **`43×43`**（depth ≤4 語）
- `H_cal = H[:7,:7]`（depth ≤2 語）— **入れ子構造が自然に出る**

### τ_H の訂正

**先に見積もった「要求 σ₇ ≥ 0.544」は約1.9倍の過大評価だった。**

- 誤：`σ_entry = 1/√n`（保守的）、`N=37`
- 正：**二項分布の上界 `σ_entry ≤ 1/(2√n)`**、`N=43`
- → `τ_H = 0.1466`、**安全基準 `σ₇ ≥ 2τ_H = 0.2933`**（2000 shots/setting）

### 正規化の決定

| 正規化 | max\|H\| | σ₁ | σ₇ | 判定 |
|---|---:|---:|---:|---|
| `‖M_u‖₂ = 1`（縮小写像） | 0.408 | 1.59 | 0.38 | **物理的**（CPTP的、`\|R(w)\|≤1` 保証） |
| スペクトル半径 = 1 | 1.687 | 8.54 | 2.20 | 非物理（非正規行列の積で成分が1を超える） |

**以降は `opnorm`（縮小写像）正規化を採用する。**

### 測定結果

サニティチェック：`r=6` → `σ₇ ≈ 1×10⁻¹⁵`（rank 6）、`r=7` → `σ₇ > 0`、`rank(H)=7` ✓

**入れ子条件 `det(H_cal)=0` を課すと σ₇ は約2.4倍落ちる**（59例、`opnorm`）：

| | σ₇(H_full) |
|---|---:|
| 制約なし `r=7` | 0.38 |
| 入れ子条件つき 中央値 | **0.162** |
| 同 95%分位 | 0.314 |
| 同 最大（59例中） | 0.388 |

**ランダム構成の合格率**（`σ₇ ≥ 2τ_H`）：

| settings/protocol | shots/setting | 2τ_H | ランダム合格率 |
|---:|---:|---:|---:|
| 1 | 2,000 | 0.2933 | **6.8%** |
| 2 | 1,304 | 0.3632 | 1.7% |
| 4 | 652 | 0.5136 | 0% |
| 7 | 372 | 0.6800 | 0% |

### 最適化すれば余裕を持ってクリアする

射影付き山登り（摂動 → `det(H_cal)=0` へ再射影 → 改善なら採用）を120反復：

```
ランダム最良（40試行）:  σ₇ = 0.402
射影付き山登り後:        σ₇ = 0.609   （改善4回のみ）
```

| settings | 2τ_H | 最適化後の判定 |
|---:|---:|---|
| 1 | 0.2933 | **クリア** |
| 2 | 0.3632 | **クリア** |
| 4 | 0.5136 | **クリア** |

### 結論

> **σ₇ の要求水準は到達可能。ステップ3–4へ進んでよい。**
>
> ただし **ランダム構成では届かない**（中央値0.162 対 要求0.293、合格率6.8%）。
> **ステップ3–4の構成は最適化して作る必要がある。** わずか120反復・4回の改善で
> 0.402 → 0.609 に到達したので、本格的な最適化ならさらに余裕が取れる。
>
> **settings ≤ 4 まで許容できる**（最適化後）。ステップ1で「二段階配分を守れるのは settings ≤ 2」
> という別の制約があるため、**実効的な上限は settings ≤ 2**。

**留意:** 上記は59–120例の実行による。1200例版は途中で停止させたため、
分位点はサンプル数が小さい。設計を凍結する前に再実行して確認すること。

## 4quater. ステップ2bis【2026-07-26 実施 — 認証対象を 8×8 minor へ変更】

ステップ3の主張抽出中に、**§4ter の判定条件が §4.2/§4.5 の凍結予算では実行できない**ことが判明した。
`scripts/minor7_smoke.py` で代替案を測定し、認証対象を変更する。

### 4quater.1 発見した不整合

**(A) 43×43 Hankel は凍結予算で測定できない。**

`σ₇(H_full)` の判定には 43×43 の全成分が要る。成分は長さ4以下の語の値であり、相異なる語は
`1+6+36+216+1296 = 1555` 個、うち深さ4が **1296** 語。深さ4の全語を 2000 shots/setting で測ると
**2,592,000 shots** となり、§4.5 の held-out 凍結値 `1.28×10⁵`（深さ4を **64 protocol** に限定）の
**20.25倍**である。

これは §1 の警告（「単にデータ点を表形式で切り分けるだけでは Hankel 部分行列にならない」）の具体的な現れ。

**(B) calibration の protocol 設計が Hankel の語構造と一致しない。**

§4.1 の calibration 46 protocol の内訳は 深さ1:6／深さ2:16／深さ3:24。一方 `H_cal`（7×7、添字は
長さ ≤1 の語）が要求するのは **長さ2以下の全語＝43語**（深さ2は36語すべて）であり、深さ3は使わない。
凍結 protocol 集合は prefix–suffix 閉包をなしておらず、深さ2を 16/36 しか測らない一方、
Hankel が使わない深さ3に 24 protocol を割いている。この状態では入れ子条件 (i) の
「calibration データ」が何を指すか確定しない。

### 4quater.2 測定結果（`scripts/minor7_smoke.py`、seed 20260726、m=6, r=7）

認証対象を「43×43 の `σ₇`」から「**行・列語がすべて長さ2の `k×k` 部分行列 `H_wit` の `σ₇`**」へ移す。
`rank H_wit ≥ 7` は `rank H_full ≥ 7` を含意する。`H_wit` の成分は長さ4の語ちょうど `k²` 個
（`|u|=|v|=2` なら `u·v` が `(u,v)` を一意に決めるため重複なし）。

二つの効果が逆向きに働く：

| 効果 | 向き |
|---|---|
| 交錯不等式 `σ₇(H_wit) ≤ σ₇(H_full)` | 構成側に**不利** |
| ノイズ閾値 `τ_H ∝ √k`（`√43 → √8`） | 判定側に**有利** |

**測定：交錯の損失の方が大きい。** 入れ子集合上のランダム構成では `σ₇(H_wit)` の中央値は
`k=7` で 0.0416、`k=8` で 0.0493（同じ点で `σ₇(H_full)` は中央値 0.3896）。
**ランダムでの合格率はどちらも 0%**（43×43 版の 6.8% より厳しい）。

射影付き山登り 1500 反復（§4ter と同じ機構）：

| minor | 深さ4語数 | 到達 `σ₇(H_wit)` | `2τ_H` @2000 | @1395 | @1000 | 判定 |
|---|---:|---:|---:|---:|---:|---|
| 7×7 | 49 | 0.1606 | 0.1183 (1.36×) | 0.1417 (1.13×) | — | クリア |
| **8×8** | **64** | **0.1934** | **0.1265 (1.53×)** | **0.1515 (1.28×)** | **0.1789 (1.08×)** | **クリア** |

同一点での `σ₇(H_full)` は 0.66–0.75 で、43×43 版の要求 0.2933 に対しては 2.3–2.6倍の余裕がある。
**余裕は交錯で失われるのであって、構成が弱いのではない。**

反復数に対して単調改善が続いており（`k=7`: 120反復 0.1247 → 400反復 0.1317 → 1500反復 0.1606）、
上表は**到達可能値の下界**であって上限ではない。**反復数が足りないと落ちる**（20反復では FAIL）。

再現：`python3 scripts/minor7_smoke.py --k 8 --iters 1500 --samples 60`（seed 既定 20260726、
NumPy 2.4.6 / SciPy 1.17.1 / Python 3.11.15）。Hankel は実現の因子分解
`H[u,v] = (M_v^T p)·(M_u c)` で構成しており（`M_w = V_{w_k}···V_{w_1}`、連接で `M_{u·v} = M_v M_u`）、
素朴な語ごと評価と最大残差 `8.3×10⁻¹⁷` で一致することを確認済み。

### 4quater.3 【凍結】ステップ2bis の決定事項

> **認証対象を「行・列語がすべて長さ2である 8×8 部分行列 `H_wit` の `σ₇`」とする。**
> **判定条件を `σ₇(H_full) > τ_H(43)` から `σ₇(H_wit) > τ_H(8)` へ差し替える。**
> **calibration の protocol 集合を「長さ2以下の全語」＝43 protocol とし、深さ3を calibration から外す。**

`k=8` を採る理由：深さ4語がちょうど **64** で §4.5 の held-out 凍結値（深さ4を64 protocol）と**過不足なく一致**し、
予算の変更が不要。かつ `k=7` より余裕が大きい（交錯により 7×7 版は 8×8 版の部分行列として下から抑えられる）。

**確定した予算（m=6）:**

| | protocol | settings=1 | settings=2 |
|---|---:|---|---|
| calibration（長さ≤2 の全語） | 43 | 2000 shots/setting、計 86,000（上限 1.2×10⁵） | 1395 shots/setting、計 120,000 |
| held-out（8×8 minor の深さ4語） | 64 | 2000 shots/setting、計 128,000（上限 1.28×10⁵） | 1000 shots/setting、計 128,000 |
| **合計** | **107** | **214,000** | **248,000** |

**settings ≤ 2 は維持される**（二段階配分 1000–2000 shots/setting の帯に収まる）。
ただし settings=2 では held-out が下限ちょうどの 1000 shots/setting となり、余裕は 1.08× まで縮む。
**settings=1 を標準設計とし、settings=2 は縮退時の許容範囲**とする。

### 4quater.4 副次的な帰結

- **認証対象が exact minor 認証と一致した。** ステップ4（SymPy で非零 7×7 minor）と、有限shot認証の対象が
  同じ 8×8 部分行列の内部になり、証明書として素直になる（従来は認証対象が 43×43 の特異値で、
  exact 認証の対象と別物だった）。
- **`σ₇(H_wit)` は 43×43 版より最適化が要る。** ランダム合格率 0%（従来 6.8%）。
  §4ter の結論「構成は最適化して作る必要がある」がより強く効く。
- **深さ3の語は calibration からも witness からも外れた。** 深さ3を使う設計へ戻す場合は予算を引き直すこと。
