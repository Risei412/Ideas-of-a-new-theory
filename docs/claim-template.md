# 主張テンプレート（各チャットに貼る）

## 使い方

1. **1チャット1主張。** 複数主張を同じスレッドで検証しない
   （モデルが自分の前の判定と整合を取ろうとし、独立な判定にならない）。
2. **提案文書をそのまま貼らない。** 文書に含まれる「なぜ新しいか」の枠付けが同調を誘導する。
   定義と命題だけを抜き出す。
3. **理論名・略称を書かない。** `DCIT` のような固有名は文脈を呼び戻し、評価を甘くする。
   中立な記号（系S、写像Φ等）に置き換える。
4. 重要な主張は**別チャットで3回**独立に実行する。
   **1回でも「還元成功」が出たら、その主張は死んだものとして扱う。**

## 貼り付け雛形

```
次の命題について、上記の手順で判定せよ。

【前提】
（設定：系の次元、開放/閉、時間依存性、その他の仮定を過不足なく）

【定義】
（新しく導入する対象・写像・量の定義。1つずつ番号を振る）

【命題】
（判定対象。1つだけ。「〜が成り立つ」の形で言い切る）

【既に検討済みの還元先】
（あれば。同じ経路の再探索を避けるため。なければ「なし」）
```

## 記入例（形式の見本。内容は架空）

```
次の命題について、上記の手順で判定せよ。

【前提】
- 有限次元ヒルベルト空間 H (dim H = d < ∞)
- 時間局所な生成子の族 {L_k}_{k=1..n}、各 L_k は GKSL 形式
- 各 L_k は個別に CPTP なダイナミクスを生成する

【定義】
D1. 族 {L_k} が「共通実装可能」であるとは、
    ある単一の system-environment 結合 H_SE と環境状態 ρ_E が存在し、
    すべての k について L_k が制御パラメータ θ_k の下での縮約から得られることをいう。

【命題】
P1. n ≥ 3 のとき、すべての L_k が個別に GKSL 形式であっても、
    族 {L_k} が共通実装可能でない場合が存在する。

【既に検討済みの還元先】
なし
```
